# 주말·대한민국 공휴일 표시

확인일: 2026-09-26. 사용자 요청: 달력의 주말과 공휴일을 명확히 표시하고, 공휴일 데이터는 라이브러리로 관리한다.

현재 `@hyunbinseo/holidays-kr@5.2027.2`의 2018~2027년 데이터를 사용한다. 직접 작성한 날짜 목록은 제거했고, 화면용 이름 변환과 제공 연도 판정만 앱에서 담당한다. 자동 갱신/API 연동은 아직 없다.

## 화면 기준

- 토요일의 요일/날짜는 파랑, 일요일과 공휴일은 붉은색으로 구분한다. 토요일이 공휴일이면 공휴일 색을 우선한다. 선택한 날짜에서도 색을 유지하고 테두리로 선택 상태를 구분한다.
- 공휴일은 연한 배경과 이름을 함께 표시한다. 모바일의 긴 이름은 필요한 만큼 줄바꿈하고, 대체공휴일은 `대체휴일`로 짧게 표시한다. 날짜를 선택하면 상세 영역에 `개천절 대체공휴일`처럼 전체 이름이 나온다. 날짜 버튼의 접근성 이름에도 요일·공휴일명을 포함한다.
- 공휴일은 사용자 일정/가계부와 별도 데이터다. 개인/공유·종류 필터, 로딩/빈 기록 상태와 관계없이 표시하고 등록 건수·금융 합계에 포함하지 않는다.
- 패키지에 포함된 대한민국 2018~2027년 공휴일을 제공한다. 실제 데이터에서 지원 연도를 판정하며, 다른 연도에서는 정보 미제공 안내와 주말 표시를 제공한다. 임의의 연도를 공휴일 없음으로 단정하지 않는다.

사용자의 후속 요청으로 달력 아래 `토 토요일 / 일 일요일·공휴일 / 대한민국 · 2018–2027` 범례를 제거했다. 날짜 색상·공휴일 이름·범위 밖 연도 안내는 유지한다. 범례 전용 스타일과 사용하지 않는 범위 문구 생성 코드도 정리했다. 이는 사용자 UI 선택이며 데이터 지원 범위는 그대로다.

날짜는 패키지의 공개 `@hyunbinseo/holidays-kr/all` export에서 가져오고 `apps/web/src/features/dayjoin/holidays.ts`에서 표시 형태로 변환한다. 2018~2027년 총 191개 날짜를 제공하며, 이 중 2026~2027년은 위 공식 자료를 대조한 기존 데이터와 전수 비교했다. 나머지 연도는 패키지 자료를 사용하며 모든 날짜를 정부 발표와 새로 대조한 것은 아니다. 2026년 명명된 공휴일 22일, 2027년 24일이며 일요일 중복을 제거한 연간 공휴일 합계는 각각 72일이다. 토요일이라는 이유로 2026-09-28(추석 다음 월요일), 현충일 다음 월요일에 대체공휴일을 만들지 않는다. 역사적/미래 날짜를 현재 규정으로 추측하지 않는다.

이는 프로젝트의 데이터 공급 방식 선택이다. 새 연도·임시공휴일 발표/지정 변경 시 패키지 릴리스와 공식 발표를 대조하고, 의존성·확인일·회귀 검사를 함께 갱신한다. 자동 최신화와 전국 이외의 지방공휴일·회사별 휴무는 구현하지 않았다. 운영 연결 시 서버에서 공식 데이터를 갱신하며 키를 웹 번들에 넣지 않는다.

## 설치 버전과 구현

React 19.3.0, Vite 8.3.1, TypeScript 6.0.3, FullCalendar React 7.1.0을 확인했다. [FullCalendar day-cell hooks 공식 문서](https://fullcalendar.io/docs/day-cell-render-hooks)와 설치된 7.1.0 타입의 `dayHeaderClass`/`dayCellTopContent`/`dayCellDidMount`를 대조했다. 표시 기능 최초 구현 시 새 의존성은 없었으며, 후속 전환에서 공휴일 패키지만 추가했다. 백엔드/schema는 변경하지 않았다.

색상·이름·배경·선택 테두리는 프로젝트 UI 결정이며 FullCalendar의 필수 디자인이 아니다. 요일은 UTC 날짜로 판정해 서울/토론토 환경에서 날짜가 이동하지 않게 했다. 웹 실행 전체 범위는 [F-002 기록](16_REACT_UI_IMPLEMENTATION.md)을 따른다.

## 최초 표시 구현 검증 (패키지 전환 전)

- 웹 테스트 24개 통과: 기존 17개 + 공휴일 회귀 7개. 토요일/일요일/공휴일 우선순위, 명절·선거일·지정 변경·대체공휴일, 미지원 연도, 연간 합계, 서울/토론토/호놀룰루 시간대 독립성을 확인했다.
- `pnpm --filter web lint`, `typecheck`, `build` 통과. API가 바뀌지 않아 API/DB 통합 검사는 다시 실행하지 않았다.
- 실제 개발 서버에서 추석 이름, 토요일 공휴일 색, 다음 달 개천절과 대체공휴일 전체 이름, 일정 필터를 켜도 공휴일 유지/기록 0건 표시, 2028년 미제공 안내를 확인했다.
- 320/360/768/1280px에서 2026년 5월의 6주 달력을 확인했다. 초기 모바일에서 라이브러리의 상속된 줄바꿈 설정 때문에 긴 이름이 옆 날짜를 침범했다. 이름에 `white-space: normal`을 명시한 뒤 네 너비 모두 가로 넘침/공휴일 이름 잘림이 없었다.
- 라이트/다크 모바일 화면을 시각 확인하고 최종 console error/warn이 없음을 확인했다. 실제 스크린리더/모바일 기기 검증이나 전체 접근성 인증을 뜻하지 않는다.

명령/실패 기록은 [실행 로그](09_SETUP_COMMANDS.log)를 따른다. 현재 변경은 로컬이며 커밋·푸시/배포는 수행하지 않았다.

## 라이브러리 전환 완료 · 2026-09-26

사용자는 라이브러리 우선 개발 원칙과 추천한 전환의 진행을 승인했다. [`@hyunbinseo/holidays-kr`](https://github.com/hyunbinseo/holidays-kr)는 우주항공청 월력요항을 가공하는 한국 공휴일 패키지다. 내부적으로는 날짜 데이터지만 이를 프로젝트에서 직접 작성하는 부담을 줄인다.

### 공식 조건과 프로젝트 선택

- npm 메타데이터와 실제 설치 파일 확인: **5.2027.2**, **MIT**, **Node >=18**, 런타임/피어 의존성 없음. 현재 Node 24.20.0, pnpm 11.24.0, React 19.3.0, Vite 8.3.1, TypeScript 6.0.3에서 검증했다. 제작자의 devEngines 버전을 소비 프로젝트에 그대로 적용하지 않았다.
- 설치된 README·package.json exports·`dist/all.d.ts`·배포 JS를 대조했다. 기본 API는 비동기 연도 로딩이고, 공개 `/all` 진입점은 `y2018`~`y2027` 데이터를 정적으로 내보낸다. 브라우저 렌더마다 비동기 조회 없이 작은 데이터를 함께 번들하는 것은 프로젝트 선택이다. 내부 파일 경로나 CDN 원격 호출에 의존하지 않는다.
- `pnpm --filter web add --save-exact @hyunbinseo/holidays-kr@5.2027.2`로 설치하고 lockfile을 갱신했다. package.json에 의존성을 수동 추가하지 않았다.
- [`date-holidays` 한국 규칙](https://github.com/commenthol/date-holidays/blob/master/data/countries/KR.yaml)은 확인 당시 노동절 규칙 누락과 설날 3일 범위 시작점 문제를 주석에 명시해 선택하지 않았다. 전체 버전 런타임 검증을 의미하지 않는다.

### 구현

- 공휴일 날짜는 모두 패키지에서 가져온다. 날짜별 목록·음력 계산·대체공휴일 생성 규칙을 앱에 중복 구현하지 않았다.
- 신정·삼일절·성탄절 등 기존 표시 이름과 대체휴일 짧은 이름을 유지한다. 지원 연도는 가져온 날짜에서 유도하며 빈 연도를 지원한다고 표시하지 않는다.
- 2025-05-05처럼 겹치는 공휴일은 모든 이름을 달력·선택일 상세·접근성 이름에 보존한다. 모바일의 24px 고정 높이를 제거해 긴 이름이 날짜 칸 밖으로 넘치지 않게 했다.
- 새 연도·임시공휴일은 **패키지 릴리스 확인 → 공식 자료 대조 → 검증한 버전으로 pnpm 업데이트 → 회귀 검사·빌드 → 배포** 순서로 반영한다. 패키지 설치는 자동 최신화가 아니다. 새로운 지원 연도가 추가되면 범위 회귀 검사도 검토한다.

### 실제 검증과 한계

- 웹 테스트 **26/26** 통과: 기존 도메인 17개 + 공휴일 9개. 겹친 공휴일, 과거 임시공휴일/선거일, 현재 규정의 과거 소급 방지, 범위 밖 안내, 시간대 독립성 등을 확인했다.
- 교체 전 2026~2027년 **46개 날짜 전체**의 날짜·전체 이름·짧은 이름·대체공휴일 원인이 교체 후와 정확히 일치했다. 비교 스냅샷은 임시 디렉터리에만 두고 제품에 두 번째 날짜 목록을 남기지 않았다.
- 웹 `typecheck`, `lint`, `build` 통과. 초기에 패키지의 서로 다른 연도별 리터럴 타입을 Object.entries에 직접 넘겨 암시적 any가 생겼다. 읽기 전용 공통 데이터 타입을 명시해 수정했으며 any 단언으로 우회하지 않았다.
- 빌드 JS 492.30 kB / gzip 148.78 kB, CSS 41.98 kB / gzip 9.37 kB. 이전 표시 구현의 JS gzip 147.49 kB 대비 약 1.29 kB 증가했다.
- 개발 브라우저에서 2025-05-05 두 공휴일 이름/0개 기록/가계부 필터 유지, 2027-05-03 노동절 대체공휴일 상세, 2028년 정보 미제공 안내를 확인했다.
- 320px에서 겹친 이름이 기존 고정 높이를 넘치는 것을 발견해 수정했다. 수정 후 320/360/768/1280px에서 페이지 가로 넘침과 공휴일 이름 영역 넘침이 없었다. 모바일 스크린샷 확인, 최종 console warn/error 없음.
- API·DB·네이티브 앱은 변경하지 않아 해당 검사를 다시 실행하지 않았다. 실제 기기/스크린리더/오프라인 재접속 검증은 이번 범위가 아니다. 커밋·푸시·배포는 수행하지 않았다.

운영 단계에서 앱 재배포 없이 임시공휴일을 반영할 필요가 생기면 공식 특일 정보 API를 Nest 서버에서 갱신하는 구조를 추가 검토한다. 최근 정상 데이터와 기준 시점·지원 범위를 보관하고 키를 웹 번들에 넣지 않는다. 서버 연동·API 키 발급·Redis·자동 업데이트 작업은 이번에 추가하지 않았다.
