# Git 브랜치 운영

적용일: 2026-09-27. 사용자 요청으로 dev와 작업별 브랜치를 분리한다. 이는 프로젝트 운영 결정이다.

| 브랜치 | 역할 | 변경 흐름 |
|---|---|---|
| `main` | 검증한 릴리스 기준 | `dev`에서 릴리스 PR |
| `dev` | 다음 릴리스의 통합 기준 | 작업 브랜치에서 PR |
| `feature/*` | 기능 개발 | 최신 `dev`에서 분기 |
| `fix/*` | 오류 수정 | 최신 `dev`에서 분기 |
| `docs/*` | 독립적인 문서 작업 | 최신 `dev`에서 분기 |

일반 기능 변경을 main/dev에 직접 커밋하거나 푸시하지 않는다. 작업 브랜치의 PR 대상을 dev로 지정하고, 검증 결과와 미완료 범위를 적는다. PR 생성·원격 저장을 병합 승인으로 해석하지 않는다. 병합은 사용자가 요청한 범위에서 진행한다.

## 이번 적용

- 원격 main을 fetch해 `05cf626` 기준으로 dev를 만들고 `origin/dev`에 게시했다.
- 누적된 달력·가계부 가상 화면, 공휴일·드롭다운, 제품 문서와 테마 설정은 `feature/calendar-ledger-ui`에서 하나의 초기 UI 작업으로 정리한다. 분기 전 미커밋 변경을 그대로 보존했다.
- 이후 독립적인 기능은 별도 브랜치를 사용한다. 예: `feature/mobile-shell`, `feature/auth`는 이름 예시이며 아직 만들지 않았다.
- 현재 UI에 의존하는 후속 작업은 해당 PR을 dev에 병합한 뒤 최신 dev에서 시작한다. 병합 전 독립 작업은 현재 dev에서 시작하고, 의존 작업을 임의의 main에서 새로 시작하지 않는다.
- CI는 main/dev 푸시와 모든 PR에서 실행한다. 작업 브랜치는 PR의 CI 결과로 검증하며 같은 커밋에 push/PR 검사를 중복 실행하지 않는다.

이 규칙은 문서와 개발 절차에 반영한 것이다. GitHub branch protection/ruleset이나 병합 강제 조건을 설정한 것은 아니다. 기본 브랜치는 main을 유지한다. 앱 공개 배포와 GitHub 소스 저장은 별도다.
