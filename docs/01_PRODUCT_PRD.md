# Dayjoin 제품·요구사항

최신 설계 방향(2026-09-26): 사용자는 **일정/가계부 등록 선택, 기록별 나만 보기/공유, 색상 구분과 함께 계좌·카드·이체를 포함한 가계부**를 원한다. 단순 수입·지출로 제한한 이전 제안을 대체한다. [통합 가계부 설계안](13_CALENDAR_RECORDS_PROPOSAL.md)에 계산·권한·공개 범위를 정리했고 아래 가계부 인수 조건과 단계에 반영했다. 기능은 아직 미구현이며 기존 일정 전용 공수는 재산정 대상이다.

플랫폼 변경(2026-09-27): 사용자 요청으로 **앱 대신 웹앱(PWA)을 먼저 제공**한다. 모바일/PC 브라우저와 홈 화면 설치를 지원하는 방향이며 월간 달력이 중심이다. 이전 앱·웹 동시 개발은 보류한다. [플랫폼 계획](15_APP_AND_WEB_PLAN.md)을 따른다.

## 문제와 첫 고객

첫 고객 가설은 **한국의 성인 2~10명이 정기적으로 일정을 공유하는 작은 모임**이다. 2026-09-26 사용자는 **첫 사용 대상을 가족·커플로 정하고, 이후 친구·모임·스터디·동호회에서도 사용하는 방향**을 확정했다. 첫 화면과 사용성 확인은 가족·커플의 사례로 진행한다. 업무 자원 예약이나 전사 일정 관리까지 한 번에 지원하지 않는다.

검증할 문제는 “대화에 약속이 흩어지고 변경 사항을 누가 확인했는지 몰라 다시 묻는다”이다. 제안 가치는 **초대 링크로 들어와 일정과 변경 내용을 함께 확인하는 짧은 흐름**이다. 고객이 이 문제를 자주 겪는지는 아직 조사하지 않았다. 기존 캘린더/메신저보다 좋다는 주장은 비교 시험 전에는 하지 않는다.

확장해서 검증할 문제는 “같이 쓴 돈은 일정과 함께 확인하고 싶지만 개인 계좌·다른 지출까지 공개하고 싶지는 않다”이다. 하나의 날짜 화면에서 일정과 금융 거래를 보고, 개인 잔액은 정확하게 관리하면서 선택한 기록만 공유하는 가치를 제안한다. 실제 필요와 사용성은 아직 검증하지 않았다.

## D-001 · 첫 사용 대상과 일정 사례

사용자 확정: 가족·커플부터 사용하고 이후 친구·모임·스터디·동호회로 넓힌다. 사용자가 우선 공유할 일정으로 **저녁식사와 여행**을 제시했다. 아래 시간 표현과 동작은 이 두 사례를 구체화한 설계 초안이며 실제 일정이나 사용성 검증 결과는 아니다. 첫 시험 그룹의 구성·규모는 실제 공유 시험 전에 확인한다.

| 사용자 제시 사례 | 누가 / 언제 / 무엇을 공유하는가 · 설계 초안 | 확인할 동작 |
|---|---|---|
| 저녁식사 | 가족 또는 커플이 특정 날짜의 식사 시작·종료 시각과 장소 등의 메모를 공유 | 시간 지정 일정 추가, 목록 조회, 약속 시간 변경 후 변경 내용 확인 |
| 여행 | 가족 또는 커플이 출발일부터 돌아오는 날까지의 기간과 여행 메모를 공유 | 여러 날짜에 걸친 일정 표시, 기간 수정, 종일/시간 지정 선택 |

첫 입력 폼은 제목, 시작·종료, 종일 여부, 메모와 대상 캘린더를 사용한다. `저녁식사`·`여행`을 필수 유형 선택이나 전용 입력 폼으로 만들지 않는다. 장소는 우선 기존 메모에 적는다. 여행도 시간을 지정할 수 있으며 모든 여행을 종일로 강제하지 않는다.

설계 선택: 공통 용어는 `그룹`, `멤버`, `일정`을 사용한다. 가족/커플 여부를 필수 가입 항목으로 추가하거나 관계별 별도 데이터 구조를 만들지 않는다. 가족 관계를 권한으로 사용하지 않고 기존 owner/editor/viewer 역할을 유지한다. 이 선택은 초기 사례를 지원하면서 다른 모임에도 같은 흐름을 적용하기 위한 프로젝트 결정이다.

기존 P0 범위의 단일 일정, 종일 일정, 개인/공유 구분을 활용한다. 자동 반복·관계 전용 기능의 우선순위는 이번 결정으로 바꾸지 않는다. 실제 계정으로 공유하는 단계에서는 인증·멤버십·권한 검증이 선행되어야 한다.

D-001 상태: **대상과 우선 사례 2개 정리**. 두 사례를 바탕으로 [D-002 화면 설계](12_SCREEN_FLOWS.md)에 목록·입력·초대 화면의 정상/빈 상태/오류를 정리하고 미리보기 동작을 확인했다. 실제 사용자 사용성은 아직 검증하지 않았다.

첫 베타의 반복 일정은 수동 복제로 대체한다. 반복 규칙과 외부 양방향 동기화가 없음을 가입/도움말에서 명확히 안내한다. 이 제한 때문에 사용할 수 없다는 의견이 반복되면 반복 일정을 앞당기되 다른 기능을 줄인다.

### 통합 가계부의 필수 범위 · 2026-09-26 추가

기존 일정 P0에 더해 단계적으로 구현할 제품 범위다. 원화 수동 입력부터 시작하는 구현 방식을 제안한다. 자동 금융기관 연동이나 실제 송금 실행은 포함하지 않는다.

| ID | 사용자 기능 | 인수 조건 |
|---|---|---|
| DJ-F01 | 현금·은행 계좌와 시작 잔액 | 본인 장부에 생성, 시작 잔액은 월 수입 제외, 거래가 있는 계정 비활성화 후 과거 기록 유지 |

| DJ-F05 | 수정·취소·환불 | 원거래 연결과 변경 이력, 누적 환불 상한, 동시 변경 충돌, 실패 시 원래 잔액 보존 |

계정 전체를 공동 관리하는 권한은 거래 한 건의 공유와 구별한다. 다른 사람의 금융 거래를 캘린더 editor가 수정하도록 허용하지 않는다. 장부 소유자가 금융 거래를 수정·취소하고 캘린더 owner의 공유 해제는 개인 원장을 삭제하지 않는 초안이다. 자세한 공개 필드와 숫자 인수 예시는 통합 가계부 설계안을 따른다.

## 권한과 삭제 정책

| 행위 | owner | editor | viewer |
|---|---|---|---|
| 공유 일정 조회 | 가능 | 가능 | 가능 |
| 공유 일정 작성/수정/삭제 | 가능 | 가능 | 불가 |
| 초대·역할 변경·그룹 삭제 | 가능 | 불가 | 불가 |
| 본인 알림 설정·탈퇴 | 가능 | 가능 | 가능 |

마지막 owner는 소유권 이전 또는 그룹 삭제 절차를 먼저 거친다. 탈퇴자는 새 요청부터 접근을 잃는다. 이미 내려받은 데이터까지 회수할 수 있다고 약속하지 않는다. 계정 삭제 시 개인 캘린더와 개인 설정은 삭제하고, 남은 그룹의 일정은 그룹 소유 데이터로 처리해 작성자 표시를 비식별화하는 정책안을 검토한다. 출시 전에 이 동작을 사용자에게 설명한다.

## 화면과 사용자 흐름

`소개 → 가입 → 그룹 생성/초대 수락 → 캘린더 → 일정 입력 → 변경 확인`.

화면은 로그인/복구, 그룹 선택, 캘린더 월/목록, 일정 편집 패널, 멤버/초대, 알림함, 설정/탈퇴의 7종으로 시작한다. 모바일 하단에는 일정·알림·설정만 두고 생성 버튼을 쉽게 찾게 한다. 날짜 선택은 키보드 입력도 지원한다. 드래그 변경은 후속 기능으로 두고 폼 편집을 먼저 완성한다.

위 7종과 하단 메뉴는 기존 일정 시안 기준이다. 최신 F-001 시안은 `캘린더 / 계좌·카드 / 월 합계`와 `+ 등록 → 일정/가계부`를 사용한다. 월간 달력을 상시 표시하고 선택일 내역·등록을 연결한다. PC 웹은 넓은 달력 옆에 내역·편집 패널을 두는 방향이다. 캘린더에서 개인 기록과 공유 기록을 함께 보되 금융 계정 관리 화면은 개인 원장 권한을 사용한다.

모든 조회 화면에 로딩·빈 상태·권한 없음·오류·재시도를 설계한다. 삭제 전 대상 일정을 표시하고 확인받는다. 저장 실패와 성공을 같은 토스트로 처리하지 않는다. 색 외에 그룹 이름/아이콘도 표시한다.

## 품질 목표와 출시 판정

- 핵심 흐름은 360px 모바일과 데스크톱에서 수평 스크롤 없이 사용. 키보드만으로 일정 생성/수정 가능.

- 한 그룹 10명·기간 내 500개 일정 fixture로 측정. 월 조회는 해당 기간만 서버에서 조회하고 무한 전체 다운로드를 하지 않는다.
- 다른 그룹 조회/쓰기, 만료/회수 초대, 탈퇴, 종일 일정, 자정 넘김, 서울/토론토 표시, 동시 수정 시나리오를 통과해야 한다.
- 통합 가계부는 이체 원자성·카드 납부 중복·재전송·동시 환불·수정/취소 후 대사와 공유 경계 시험을 추가 통과해야 한다. 미공유 금융 정보는 건수나 잔액으로도 다른 멤버에게 노출되지 않아야 한다.
- 같은 계정으로 모바일/PC 브라우저와 설치형 PWA에서 재조회한 기록이 일치해야 한다. 모바일 키보드·안전 영역·로그인 복귀·업데이트와 PC 키보드 조작을 검증한다. 실제 인증·저장·공유는 아직 미구현이다.
- 무료 환경의 중지나 메일 지연을 제품의 보장 SLA로 표현하지 않는다.

## 검증 지표

활성화는 그룹 생성 후 7일 안에 **두 번째 실제 멤버 합류 + 공유 일정 3개 작성**으로 정의한다. 4주 재사용은 활성화 그룹 중 4번째 주에 2명 이상이 조회/편집한 그룹 비율이다. 내부 계정·테스트 이벤트는 제외한다.

초기 의사결정 기준안: 5개 시험 그룹 중 3개 이상 활성화, 2개 이상 4주째 사용. 표본이 작으므로 시장 성공률로 일반화하지 않는다. 활성화가 낮으면 기능 확장보다 초대/첫 일정 흐름을 고친다. 지표에는 일정 제목/메모를 수집하지 않는다.

위 활성화는 일정 흐름의 지표다. 가계부에서는 계정·거래 입력의 지속 사용과 기록상 잔액 대조, 선택적 공유의 이해도를 별도로 확인한다. 금액·계정명·거래 메모를 분석 이벤트에 수집하지 않는다. 금융 기능의 목표 수치는 사용 시험을 설계할 때 정한다.
