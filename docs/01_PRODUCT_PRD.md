# Dayjoin 제품·요구사항

## 문제와 첫 고객

첫 고객 가설은 **한국의 성인 2~10명이 정기적으로 일정을 공유하는 작은 모임**이다. 가족·커플·친구·스터디를 포함하되 초기 인터뷰는 한 유형에 집중한다. 업무 자원 예약이나 전사 일정 관리까지 한 번에 지원하지 않는다.

검증할 문제는 “대화에 약속이 흩어지고 변경 사항을 누가 확인했는지 몰라 다시 묻는다”이다. 제안 가치는 **초대 링크로 들어와 일정과 변경 내용을 함께 확인하는 짧은 흐름**이다. 고객이 이 문제를 자주 겪는지는 아직 조사하지 않았다. 기존 캘린더/메신저보다 좋다는 주장은 비교 시험 전에는 하지 않는다.

## 단계별 제품

| 단계 | 범위 | 성공 판정 |
|---|---|---|
| v0 개인 사용 | 가상/개인 데이터로 일정 생성·수정·삭제, 월/목록 보기 | 본인이 일주일 사용하고 입력 불편 3개를 수정 |
| v0.1 초대 베타 | 실제 계정, 그룹/역할, 공유 일정, 변경 알림, 기본 내보내기/탈퇴 | 5개 그룹이 핵심 흐름을 시험하고 권한·시간 오류가 해결됨 |
| v1 유료 검증 | 반복 일정, 알림 개선, 그룹 요금과 결제, 운영 복구 체계 | 반복 사용과 지불 의향을 확인한 뒤 결제 시험 통과 |

첫 베타의 반복 일정은 수동 복제로 대체한다. 반복 규칙과 외부 양방향 동기화가 없음을 가입/도움말에서 명확히 안내한다. 이 제한 때문에 사용할 수 없다는 의견이 반복되면 반복 일정을 앞당기되 다른 기능을 줄인다.

## MVP 기능과 인수 조건

P0는 초대 베타에 필요, P1은 사용 검증 후, P2는 후속 확장이다.

| ID | 우선 | 사용자 기능 | 완료 조건 |
|---|---|---|---|
| DJ-01 | P0 | 가입·로그인·복구 | 확인된 이메일로 로그인, 오류/만료 링크 안내, 로그아웃 시 이전 그룹 정보가 남지 않음 |
| DJ-02 | P0 | 그룹/캘린더 만들기 | 생성자는 owner, 기본 캘린더 1개 생성, 그룹 이름 변경 가능 |
| DJ-03 | P0 | 초대와 멤버 권한 | owner가 editor/viewer 링크 발급·회수, 7일 만료, 초대 수락 전 그룹 데이터 비공개 |
| DJ-04 | P0 | 일정 작성 | 제목·시작/종료·종일·메모 저장, 종료 역전 거부, 저장 실패 시 입력 보존 |
| DJ-05 | P0 | 수정·삭제·변경 확인 | editor 변경 가능, 작성자/변경 시각 표시, 다른 사람 변경 알림 확인, 동시 수정 충돌 안내 |
| DJ-06 | P0 | 월/목록 보기 | 모바일 목록 기본, PC 월 보기, 기간 필터, 그룹별 색과 텍스트 구분 |
| DJ-07 | P0 | 개인 일정과 공유 구분 | 개인 캘린더는 본인만 접근, 개인 일정 작성으로 그룹에 자동 공개되지 않음 |
| DJ-08 | P0 | 인앱 알림 | 그룹 변경 알림은 읽지 않음/읽음 표시, 탈퇴 후 새 알림 없음 |
| DJ-09 | P0 | 기본 데이터 통제 | 권한 있는 캘린더 일정 JSON/CSV 내보내기, 본인 탈퇴/계정 삭제 요청 처리 |
| DJ-10 | P1 | 반복 일정 | 매주 요일/종료일 규칙, 해당 회차/전체 수정, 예외·종료일 처리 테스트 |
| DJ-11 | P1 | 이메일 리마인더 | 사용자가 선택한 알림 1회, 재시도 중 중복 억제, 취소/시간 변경 시 이전 알림 취소 |
| DJ-12 | P2 | 참석 응답·시간 후보 | 실제 그룹에서 조율 필요성이 확인되면 추가 |

P0 초대는 링크 복사로도 가능하다. owner/editor/viewer는 그룹 안의 모든 공유 캘린더에 동일하게 적용한다. 캘린더별 별도 권한은 후속 범위다. 개인 캘린더는 별도 개인 작업 공간에 있어 그룹 역할과 섞이지 않는다.

## 권한과 삭제 정책

| 행위 | owner | editor | viewer |
|---|---|---|---|
| 공유 일정 조회 | 가능 | 가능 | 가능 |
| 공유 일정 작성/수정/삭제 | 가능 | 가능 | 불가 |
| 초대·역할 변경·그룹 삭제 | 가능 | 불가 | 불가 |
| 본인 알림 설정·탈퇴 | 가능 | 가능 | 가능 |

마지막 owner는 소유권 이전 또는 그룹 삭제 절차를 먼저 거친다. 탈퇴자는 새 요청부터 접근을 잃는다. 이미 내려받은 데이터까지 회수할 수 있다고 약속하지 않는다. 계정 삭제 시 개인 캘린더와 개인 설정은 삭제하고, 남은 그룹의 일정은 그룹 소유 데이터로 처리해 작성자 표시를 비식별화하는 정책안을 검토한다. 출시 전에 이 동작을 사용자에게 설명한다.

## 화면과 사용자 흐름

`소개 → 가입 → 그룹 생성/초대 수락 → 캘린더 → 일정 입력 → 변경 확인`.

화면은 로그인/복구, 그룹 선택, 캘린더 월/목록, 일정 편집 패널, 멤버/초대, 알림함, 설정/탈퇴의 7종으로 시작한다. 모바일 하단에는 일정·알림·설정만 두고 생성 버튼을 쉽게 찾게 한다. 날짜 선택은 키보드 입력도 지원한다. 드래그 변경은 후속 기능으로 두고 폼 편집을 먼저 완성한다.

모든 조회 화면에 로딩·빈 상태·권한 없음·오류·재시도를 설계한다. 삭제 전 대상 일정을 표시하고 확인받는다. 저장 실패와 성공을 같은 토스트로 처리하지 않는다. 색 외에 그룹 이름/아이콘도 표시한다.

## 품질 목표와 출시 판정

- 핵심 흐름은 360px 모바일과 데스크톱에서 수평 스크롤 없이 사용. 키보드만으로 일정 생성/수정 가능.
- 한국 모바일 네트워크를 가정한 시험에서 첫 목록 표시 3초 이내, 일반 조회 p95 1초 이내를 목표로 한다. 측정 기기·네트워크·데이터 크기를 결과와 같이 기록한다.
- 한 그룹 10명·기간 내 500개 일정 fixture로 측정. 월 조회는 해당 기간만 서버에서 조회하고 무한 전체 다운로드를 하지 않는다.
- 다른 그룹 조회/쓰기, 만료/회수 초대, 탈퇴, 종일 일정, 자정 넘김, 서울/토론토 표시, 동시 수정 시나리오를 통과해야 한다.
- 무료 환경의 중지나 메일 지연을 제품의 보장 SLA로 표현하지 않는다.

## 검증 지표

활성화는 그룹 생성 후 7일 안에 **두 번째 실제 멤버 합류 + 공유 일정 3개 작성**으로 정의한다. 4주 재사용은 활성화 그룹 중 4번째 주에 2명 이상이 조회/편집한 그룹 비율이다. 내부 계정·테스트 이벤트는 제외한다.

초기 의사결정 기준안: 5개 시험 그룹 중 3개 이상 활성화, 2개 이상 4주째 사용. 표본이 작으므로 시장 성공률로 일반화하지 않는다. 활성화가 낮으면 기능 확장보다 초대/첫 일정 흐름을 고친다. 지표에는 일정 제목/메모를 수집하지 않는다.

제외: Google/Apple 양방향 연동, 공휴일 데이터 자동 수집, 자원/회의실 예약, 공개 검색 캘린더, 네이티브 앱, 실시간 채팅, AI 일정 추천, 오프라인 수정.
