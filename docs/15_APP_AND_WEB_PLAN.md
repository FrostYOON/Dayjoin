# 모바일 앱과 웹 제공 방향

작성일: 2026-09-26. 상태(2026-09-27 갱신): **F-002 완료·P-010 앱 프로젝트 생성 및 웹 자산 동기화 완료**. 네이티브 빌드·기기 실행·스토어 배포·기기 간 업무 동기화는 미완료다. 최신 버전과 실행 조건은 [앱 구성 기록](22_MOBILE_SHELL.md)을 따른다. 아래 기술 비교와 미설치 내용은 최초 제안 시점의 기록이다.

## 사용자 요청과 화면

사용자는 모바일 앱과 웹 버전을 모두 원한다. 기존의 모바일 앱 제외 방침을 변경한다. 월간 달력을 첫 화면의 중심으로 두는 ADR-D09와 따뜻한 색감·둥근 화면은 두 환경에 공통 적용한다. iOS/Android를 앱 대상의 기본 제안으로 두며 OS별 첫 출시 순서와 최소 지원 버전은 아직 정하지 않았다.

| 환경 | 제안하는 화면 | 주요 조작 |
|---|---|---|
| 모바일 앱 | 월간 달력 → 선택일 내역, 하단 주요 메뉴 | 터치로 날짜 선택, 선택일에 일정/가계부 등록, 계좌·카드 확인 |
| PC 웹 | 왼쪽 캘린더/메뉴, 가운데 넓은 월간 달력, 오른쪽 선택일 내역·편집 | 마우스·키보드로 날짜 이동/입력, 넓은 화면에서 기간과 내역 함께 확인 |
| 모바일 웹 | 좁은 화면에 맞춘 달력과 선택일 내역 | 설치 없이 같은 계정의 일정·가계부 이용 |

PC 폭에서 휴대폰 프레임을 그대로 확대하지 않고 달력과 상세 영역을 함께 배치한다. 폭이 줄면 상세 영역을 아래로 옮긴다. 기능·공개 범위·금액 규칙은 같고 내비게이션과 배치는 화면 크기 및 실행 환경에 맞춘다.

## 구현 방식 제안

**현재 권장: React + Vite + TypeScript 화면을 공통으로 만들고 Capacitor로 iOS/Android 앱을 구성한다.** 기존 확정 스택과 1인 개발 조건을 고려한 프로젝트 추천이며 사용자가 Capacitor라는 기술을 직접 지정한 것은 아니다.

| 후보 | 장점 | 추가 부담과 판단 |
|---|---|---|
| React/Vite + Capacitor | 웹 UI와 많은 로직을 재사용하고 기존 프로젝트에서 앱으로 확장 | 웹 UI를 네이티브 컨테이너에서 실행한다. 키보드·뒤로가기·안전 영역·로그인 복귀·네이티브 플러그인은 실기기 조정 필요. 초기 권장 |
| React Native + Expo, 웹은 기존 Vite | 네이티브 모바일 UI를 중심으로 구현 가능 | Vite 웹 UI와 네이티브 UI를 각각 관리하며 공유 범위를 계약·유틸리티 위주로 설계해야 한다. 네이티브 상호작용 요구가 커질 때 재검토 |

Capacitor는 기존 JavaScript 프로젝트에 추가할 수 있고, 웹 빌드 산출물을 네이티브 프로젝트에 동기화하는 방식을 제공한다. 앱을 감싸기만 하면 모든 모바일 동작이나 스토어 출시가 완료되는 것은 아니다. 필요한 플랫폼 기능만 추가한다. 푸시·홈 화면 위젯·생체 인증은 이번 플랫폼 요청만으로 첫 버전 필수 기능에 추가하지 않는다.

## 공유하는 것과 분리하는 것

- 같은 Dayjoin 계정, Nest API, PostgreSQL 업무 데이터를 사용한다. 앱과 웹에 별도 금융 원장을 만들지 않는다. 다른 서비스의 DB/Auth/배포 독립 원칙은 유지한다.
- 입력 모델·API 계약·금액/날짜 표시·권한에 따른 화면 동작은 재사용한다. 최종 금액 계산·변경 권한·멱등성·동시 수정 판단은 서버가 수행한다.
- 화면 배치, 키보드/뒤로가기, 인증 콜백, 토큰 보관, 파일 내보내기와 알림은 환경에 맞는 구현과 검증을 둔다. 웹의 쿠키/CORS 동작을 앱에서도 자동으로 같다고 가정하지 않는다.
- 한 환경에서 저장한 기록을 다른 환경에서 재조회하면 같은 내용·잔액·공개 범위를 보여야 한다. 첫 버전은 진입/복귀/명시적 새로고침 시 재조회하는 방향이며 즉시 실시간 반영과 오프라인 수정은 별도 범위다.
- 웹 배포와 앱 바이너리 배포는 구분한다. 이전 앱 버전과 서버 API가 함께 동작하는 호환성도 확인한다.

## 개발 순서와 인수 조건

1. **F-002 완료:** 공통 React 화면에 모바일 달력과 PC의 넓은 달력/내역 배치를 구현했다. 입력·상세는 공통 모달이며 가상 데이터 단계다. [검증 결과](16_REACT_UI_IMPLEMENTATION.md)를 따른다.
2. **P-010:** 첫 화면/등록 흐름으로 Capacitor 적용 가능성을 조기에 검증한다. 공식 CLI로 플랫폼 프로젝트를 만들고 iOS/Android에서 날짜 선택·키보드·뒤로가기·안전 영역을 확인한다. 해당 작업 착수 시 버전/개발 도구 조건을 고정한다.
3. 기존 D/F 작업으로 실제 인증·일정·개인 원장·공유 API를 연결한다. **P-020:** 같은 계정의 앱/웹 재조회 일치, 저장 실패·중복 요청·동시 수정·로그아웃·비공개 기록 경계를 확인한다.
4. **P-030:** 웹 배포와 앱 테스트 배포/스토어 제출 준비를 각각 수행한다. OS별 실기기 검증·서명·계정·제출 조건은 해당 시점에 확인한다. 출시일과 동시 출시는 아직 약속하지 않는다.

기존 160~220시간은 일정 전용의 과거 추정이다. 금융 원장과 앱/웹을 포함한 총 공수로 재사용하지 않는다. 최초 플랫폼 결정에서는 문서만 변경했다. 후속 F-002에서 React 화면을 완료했으며 P-010~030은 미완료다.

## 공식 근거와 버전 확인 · 2026-09-26

설치 확인: React 19.3.0, Vite 8.3.1, TypeScript 6.0.3. Capacitor/Expo는 미설치이며 플랫폼 CLI 생성이나 네이티브 도구 호환성을 시험하지 않았다. 웹 추가 패키지의 실제 설치 버전은 F-002 기록을 따른다.

- [Capacitor 소개 · v8 문서](https://capacitorjs.com/docs): 기존 웹 프로젝트와 네이티브 기능을 연결하는 공식 지원 방식. 채택은 프로젝트 선택이다.
- [Capacitor 개발 흐름](https://capacitorjs.com/docs/basics/workflow): 웹 빌드 → 네이티브 프로젝트 동기화 → 기기 실행/빌드 절차. core/iOS/Android 버전을 맞추는 공식 지침을 설치 때 적용한다.
- [Capacitor 설치](https://capacitorjs.com/docs/getting-started): 실제 추가 시 공식 CLI 및 선행 조건과 대조한다. 현재 문서의 최신 버전을 그대로 설치한 것으로 간주하지 않는다.
- [Expo 공식 문서](https://docs.expo.dev/): iOS/Android/웹을 대상으로 하는 대안. Expo로 웹까지 통합하는 것도 가능하지만 현재 확정한 Vite 구성을 바꾸는 별도 설계 선택이다.

사용자 확정은 **앱과 웹 모두 제공**이다. Capacitor 선택, OS별 지원 범위, 화면의 세부 배치와 구현 순서는 공식 문서를 참고한 제안이다.
