# Dayjoin 새 채팅 인계

## 최신 우선 기준 · 2026-09-27

사용자가 앱 대신 **웹앱(PWA)**으로 사용하기로 했다. 아래 과거 앱 진행 순서보다 이 결정이 우선한다. `feature/web-pwa`는 최신 dev에서 분기해 manifest/아이콘, 설치 안내, 선택형 업데이트와 공개 정적 자산 캐시를 구현한다. 실제 상태·검증은 [PWA 기록](24_PWA_IMPLEMENTATION.md)을 따른다. `feature/mobile-shell` / Draft PR #4의 네이티브 작업은 보류·보존하며 병합/삭제하지 않는다. Xcode는 웹앱 작업의 선행 조건이 아니다. 다음 요청에서 웹 로그인·일정 영속 저장·공유를 진행하고, HTTPS 배포 후 실제 휴대폰 설치를 검증한다. 현재 업무 데이터는 메모리 예시이며 실제 인증·RLS·금융 원장·공유·푸시·오프라인 수정은 미구현이다.


## 사용자 의도와 현재 범위
Dayjoin은 일정과 계좌·카드·이체를 포함한 가계부를 한 캘린더에서 관리하고 기록별로 공유하는 서비스로 범위를 넓혔다. 한국 우선, 1인 개발, 주 약 10시간. 사용자는 TypeScript·NestJS 경험이 가장 많고 프론트엔드는 입문 단계다. 초기 비용을 줄이면서 직접 사용하고 장기적으로 수익화하려 한다.
세 프로젝트 기초 세팅 후 이 채팅에서 Dayjoin GitHub 연결과 초기 커밋·푸시를 완료했다. 이후 사용자는 **가족·커플부터 사용하고, 친구·모임·스터디·동호회까지 확대**하는 방향을 확정했고, 우선 공유할 일정으로 **저녁식사와 여행**을 제시했다. 다음 단계 진행 요청에 따라 D-002의 화면 흐름과 미리보기를 작성했다. 이 인계만으로 후속 로그인/제품 기능을 자동 개발하지 않는다.

## 완료한 기초 세팅
- React + Vite + TypeScript, NestJS + Express, pnpm workspace.
- 환경 변수 검증, 입력 검증/보안 헤더 기반, DB/선택적 Redis 모듈, health API.
- PostgreSQL/Redis/API Docker Compose, 비루트 다단계 API 이미지, CI workflow 파일.
- 고정 도구 버전과 lockfile, 공식 CLI 명령 기록, 로컬 검사/실제 연결 검증.
- 프로젝트별 포트/DB/volume 분리. 이 프로젝트: 웹 5173, API 3000, PostgreSQL 15432, Redis 16379, 통합 검사 3300.
- Git 기본 브랜치 `main`, 원격 `origin`: https://github.com/FrostYOON/Dayjoin.git. 2026-09-26 사용자 요청으로 연결했다. 저장소는 연결 당시 Public이며, CI 실제 결과는 GitHub Actions에서 확인한다.
- 초기 커밋 `05cf626`의 [GitHub CI 실행](https://github.com/FrostYOON/Dayjoin/actions/runs/36265647811) 성공을 확인했다. 빌드·lint·typecheck·단위/HTTP 계약·실제 DB/Redis 통합 검사·API 컨테이너 실행이 통과했다. 이후 변경의 검증 결과와 구분한다.

## 미완료 범위
웹은 F-002의 React 달력·일정/가계부·계좌·카드·월 합계 화면이다. 예시 데이터만 메모리에 저장하며 새로고침하면 초기화된다. 업무 모델/migration/RLS, 로그인/JWT·초대·업무 권한, 도메인 기능·결제와 클라우드 배포는 없다. GitHub CI 통과 여부는 해당 커밋의 실행 결과로 판단한다.
도메인 데이터가 없어 빈 migration을 임의로 만들지 않는다. Redis는 캐시 연결 기반이며 업무 캐시/영속 작업 큐는 구현하지 않았다.
D-001에서 가족·커플 대상과 **저녁식사·여행** 사례를 정리했고, D-002에서 일정 목록·입력·초대·수락의 설계 산출물을 완료했다. 이후 F-001에서 통합 등록과 계좌·카드 시안을 추가하고 아래 결과를 확인했다. React 화면 작업은 F-002로 확장해 가상 데이터 화면까지 완료했다. 실제 사용성은 미검증이고 첫 시험 그룹의 구성·규모는 실제 공유 시험 전에 확인한다. 그룹 역할은 유지하지만 금융 원장 수정 권한은 캘린더 역할과 별도로 구분한다.

최신 디자인 피드백: 초록색 고정은 불필요하며 **부드럽고 따뜻한 색감 + 둥근 화면**을 선호한다. D-002 미리보기를 아이보리·살구 포인트·둥근 일정 행으로 수정했다. 다크 모드는 따뜻한 차콜이다. 후속 화면은 이 방향을 기준으로 하되 정확한 브랜드 색상은 제안 상태다. 상세 근거·검증은 12_SCREEN_FLOWS.md와 ADR-D06을 따른다.

이후 사용자가 **처음부터 달력이 메인인 화면**을 요청했다. F-001 시안을 월간 달력 상시 표시 → 필터 → 선택일 내역/등록으로 수정했다. 달력 접기는 제거하고, 선택한 날짜를 등록 폼에 반영하며 저장 후에도 유지한다. 비교 설정은 화면 아래에 접어서 배치했다. 후속 F-002는 이 달력 중심 구성을 기준으로 하며 상세 변경/검증은 14_UNIFIED_SCREEN_PREVIEW.md와 ADR-D09를 따른다.

최신 플랫폼 요청은 **모바일 앱과 웹 버전을 모두 제공**하는 것이다. PRD의 앱 제외 항목을 제거했다. 초기 추천은 기존 React/Vite 화면 + Capacitor 앱 구성이고, iOS/Android는 기본 제안이며 최소 지원 버전/출시 순서는 미정이다. 모바일과 PC 웹은 폭에 맞는 배치를 사용하며 같은 Dayjoin 계정/API/업무 데이터를 공유한다. Capacitor를 사용자가 직접 선택했다고 쓰지 않는다. Capacitor 설치·앱 프로젝트·네이티브 빌드·스토어 등록·동기화는 아직 없다. F-002에서 모바일/PC 반응형 웹을 구현했고 다음 P-010에서 기기 적합성을 확인한다.

최신 기능 방향: 사용자는 `일정/가계부`를 골라 등록하고 각 내역을 `나만 보기/캘린더에 공유`로 선택하며, **계좌·카드·이체까지 포함**하기를 원한다. 단순 수입·지출로 제한하던 제안을 대체했다. 색상으로 종류를 구분하고 공개 범위는 문구·아이콘으로 표시한다. 개인 계좌 잔액과 거래 한 건의 공개 정보는 분리한다. 원화 수동 등록부터 구현하는 것은 프로젝트 제안이며 금융기관 연동·실제 송금·Cashjoin 병합/중단을 확정하지 않았다. 통합 가계부 공수는 미산정이며 이전 일정 전용 추정을 재사용하지 않는다.

사용자의 진행 요청으로 F-001 통합 시안을 별도로 작성했다. 계좌/카드 추가·이체/납부·부분 환불·수정/취소·월 합계·개인/공유 비교는 브라우저의 가상 데이터에서 동작한다. 다크 54개/라이트 12개 배치와 관련 흐름을 확인했고 상세는 14_UNIFIED_SCREEN_PREVIEW.md를 따른다. **F-002 React 가상 화면 구현을 완료했다.** API 단위 6개·웹 도메인 17개, 전체 lint/typecheck, 웹 build가 통과했다. 브라우저에서 15개 반응형 배치와 주요 흐름을 확인했다. 상세 결과는 16_REACT_UI_IMPLEMENTATION.md를 따른다. 다음은 P-010 기기 적합성 확인이며 인증·금융 원장·실제 공유는 아직 없다. 초기 커밋 이후 변경은 로컬에 있으며 이번 F-002에서 커밋·푸시하지 않았다.

## 준수할 실행 방식
2026-09-26 사용자는 **라이브러리로 가능한 부분은 최대한 라이브러리를 사용하는 개발 방식**을 요청했다. AGENTS와 08_ENGINEERING_STANDARD.md에 선정·호환성·유지보수·검증 기준을 반영했다. 후속 진행 승인으로 공휴일은 `@hyunbinseo/holidays-kr@5.2027.2`로 교체했다. 공식 pnpm CLI 설치/lockfile 갱신, 공개 `/all` 데이터 연결, 2018~2027년 범위 표시와 겹친 공휴일/긴 이름 처리를 완료했다. 자동 갱신·서버 API 연동은 아직 없다. 이후 사용자 요청으로 달력 하단의 주말·공휴일 범례와 대한민국/지원 연도 문구를 제거했다. 날짜 색상과 공휴일 이름, 미지원 연도 안내는 유지한다.

후속 요청으로 주말/공휴일 표시를 보완했다. 토요일 파랑, 일요일·공휴일 붉은색, 공휴일 이름/선택일 안내를 제공한다. 현재 날짜 데이터는 패키지에서 가져오며 범위 밖에는 미제공 안내를 표시한다. 기존에 공식 발표와 대조한 2026~2027년 46개 날짜/표시 이름이 교체 후 전부 일치했다. 최신 웹 테스트는 기존 17개에 공휴일 9개를 더한 26개가 통과했고 웹 lint/typecheck/build도 통과했다. 320/360/768/1280px에서 중복 이름 넘침 수정과 범위 밖 안내를 확인했다. 데이터 갱신 기준과 실제 검증은 17_KOREAN_HOLIDAYS.md를 따른다.

작업 전 설치 버전에 맞는 공식 문서를 확인하고 필수 조건과 프로젝트 선택을 구분한다. 설치·생성·모듈 추가·빌드는 실제 터미널 공식 CLI로 실행한다. 실행하지 않은 검사를 완료로 기록하지 않는다.
기존 공통 기반을 불필요하게 다시 생성하지 말고 현재 파일과 검증 기록을 활용한다. 서비스별 저장소/DB/배포를 독립적으로 유지한다. README의 예시 비밀번호는 로컬 전용이다.

2026-09-27 드롭다운 디자인 피드백을 반영해 `@radix-ui/react-select@2.3.7`을 CLI로 설치하고 필터·설정·기록·계좌 폼의 선택 메뉴를 공통화했다. 둥근 메뉴, 선택 체크, 다크 모드, 키보드 선택, 네이티브 dialog 안의 포털과 Escape 처리를 확인했다. 웹 lint/typecheck/build와 기존 테스트 26개가 통과했다. JS 청크 578.54 kB로 Vite의 500 kB 초과 경고가 남아 있으며 실제 기기/스크린리더는 미검증이다. 상세는 18_DROPDOWN_UI.md를 따른다. 이번에도 커밋·푸시하지 않았다.

2026-09-27 사용자가 GitHub 저장과 dev/작업별 브랜치 분리를 요청했다. 초기 main 기준 dev를 원격에 만들었고, 누적 UI는 `feature/calendar-ledger-ui`에서 보존·정리한다. PR 대상은 dev이며 병합은 별도다. 최신 시스템 테마·저장 구현은 `next-themes@0.4.6`을 사용한다. 전체 lint/typecheck, API 6개·웹 26개·HTTP 계약 5개, 전체 build가 통과했다. 기존 Prisma 전이 의존성 보안 권고 3건과 웹 청크 경고는 미해결 후속 항목이다. 이전 문단의 미커밋 상태는 각 작업 당시 기록이며 현재 Git/PR 상태는 실제 원격을 확인한다. 테마와 검증의 상세는 20_THEME_AND_UI_CHECKPOINT.md를 따른다. 다음은 현재 PR 검토·dev 통합 및 의존성 보완, 이후 P-010 앱 실행 검증 → 인증/일정 저장 → 실제 공유 → 금융 원장 연결 순서다.
