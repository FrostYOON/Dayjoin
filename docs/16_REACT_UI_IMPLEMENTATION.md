# F-002 React 통합 화면 구현

확인일: 2026-09-26 (America/Toronto). 상태: **가상 데이터 React 웹 화면 완료**. 모바일 앱 패키징, 실제 인증·공유·영속 저장은 후속 작업이다.

## 화면과 동작

`apps/web`의 공식 예제를 실제 Dayjoin 화면으로 교체했다. 월간 달력을 첫 화면으로 열고 선택한 날짜의 일정과 가계부를 함께 보여 준다. 모바일은 달력 아래에 내역과 하단 메뉴, PC는 왼쪽 메뉴·가운데 달력·오른쪽 내역을 배치한다. 입력·상세는 공통 모달을 사용한다. 아이보리·살구색과 둥근 형태, 따뜻한 차콜 다크 모드를 제공한다.

- 일정: 제목, 기간, 종일/시간, 메모, 개인/공유, 등록·수정·취소. 종일 종료일은 포함하고 시간 일정의 자정 종료는 다음 날짜에서 제외한다. 입력 기준은 서울 시간이다.
- 가계부: 수입·지출·이체·신용카드 납부·부분 환불. 원화 정수 문자열과 `BigInt`로 계산한다. 이체/납부는 수입·지출에서 제외하고 환불은 순지출에서 차감한다.
- 계좌·카드: 본인 소유 은행/현금/신용카드/체크카드 추가, 시작 잔액, 체크카드 은행 연결, 관련 내역. 시작 잔액은 수입에 넣지 않는다.
- 월 합계: 내 장부와 공유 캘린더를 구분하고 분류별 순지출을 표시한다.
- 관점·상태 비교: 상단 프로필의 미리보기 설정에서 지우/하늘, 밝기, 로딩/오류, 다음 저장 실패, 예시/빈 데이터 초기화를 선택한다.
- 다른 멤버의 개인 기록은 달력 표시·건수·목록에서 제외한다. 공유받은 금융 상세에는 계좌 식별자·별칭·잔액을 제공하지 않으며 수정 동작도 제공하지 않는다.
- 입력 오류를 필드에 표시하며 저장 실패 때 초안을 유지한다. 작성 중 닫기는 버리기 확인을 거친다. 모달 닫기 후 이전 버튼으로 포커스를 돌린다.

## 구현 경계

| 파일 | 책임 |
|---|---|
| `apps/web/src/App.tsx` | 화면 전환, 선택일/월, 필터, 모달, 예시 상태 |
| `features/dayjoin/MonthCalendar.tsx` | FullCalendar 월 그리드, 날짜별 표시, 키보드 이동 |
| `features/dayjoin/model.ts` | 입력·소유자 검증, 날짜/금액, 공개 화면용 필드 제한, 잔액/합계 |
| `features/dayjoin/seed.ts` | 가상 인물과 현재 서울 날짜 기준 예시 |
| `features/dayjoin/RecordForm.tsx`, `RecordDetail.tsx` | 일정·금융 입력과 상세/정정 동작 |
| `features/dayjoin/Accounts.tsx`, `Reports.tsx`, `ui.tsx` | 계좌·카드, 월 합계, 공통 표시/모달 |
| `apps/web/tests/model.test.ts` | 도메인 계산·검증 회귀 검사 17개 |

`features/...`는 `apps/web/src` 아래다. 가상 데이터는 React 메모리에만 있다. 새로고침하면 초기화되며 실제 금융 정보 입력용이 아니다. 화면에서 숨기는 코드와 가상 인물 전환은 **인증/권한 경계가 아니다**. 향후 서버는 공개 응답 필드를 제한하고 작성 권한·정밀도·동시 환불·원자성·멱등성을 독립 검증해야 한다. 데모 취소는 메모리에서 제거하지만 실제 금융 원장은 정정 이력을 보존해야 한다.

앱 재사용을 고려한 반응형 웹까지 구현했다. Capacitor 프로젝트, 앱 바이너리, 앱스토어 배포와 기기 간 동기화는 구현하지 않았다. 계좌 별칭 수정/비활성화, 초대/로그인/알림, 운영 API, 대량 거래·오프라인 처리는 후속 범위다. 다음 단계는 [P-010 기기 적합성 확인](15_APP_AND_WEB_PLAN.md)이다.

## 버전과 공식 근거

설치 확인: Node **24.20.0**, pnpm **11.24.0**, React **19.3.0**, Vite **8.3.1**, TypeScript **6.0.3**. 추가 설치: `@fullcalendar/react` **7.1.0**, `temporal-polyfill` **1.0.1**, `lucide-react` **1.48.0**. 기존 저장소의 Prettier **3.9.9**로 소스를 정리했다.

| 구분 | 근거와 적용 |
|---|---|
| 공식 호환 조건 | [FullCalendar React v7](https://fullcalendar.io/docs/react)와 7.1.0 registry peerDependencies: React 17~19, temporal-polyfill ^1.0.1. 기존 React 19.3.0과 대조하고 CLI로 설치했다. |
| 공식 API | [dayGrid](https://fullcalendar.io/docs/daygrid-view), [day-cell hooks](https://fullcalendar.io/docs/day-cell-render-hooks). v7의 React 패키지 내 daygrid/theme/locale 경로와 skeleton/theme CSS를 사용했다. v6의 별도 패키지 구조를 복사하지 않았다. 설치된 `.d.ts`와 실제 렌더링으로 확인했다. |
| 공식 지원 선택지 | [Lucide React](https://lucide.dev/guide/react)의 React SVG 아이콘을 필요한 항목만 import한다. 설치한 1.48.0의 peerDependencies도 확인했다. |
| 공식 런타임 기능 | [Node 24 TypeScript 실행](https://nodejs.org/docs/latest-v24.x/api/typescript.html): 타입 제거로 `.ts` 테스트 실행. 문서의 패치 버전은 설치 버전보다 높아 실제 24.20.0 실행과 TypeScript 검사를 함께 확인했다. |
| 프로젝트 선택 | 월 그리드의 날짜별 내용을 공개 hook으로 구성한다. 서울의 오늘을 명시하고 날짜 그리드는 UTC로 렌더링해 브라우저 시간대의 날짜 이동을 막는다. 운영 시간대 저장 계약은 아직 구현하지 않았다. |
| 프로젝트 선택 | 현재 화면 전환은 React 상태로 관리한다. API·라우터·전역 상태 라이브러리는 이 가상 화면을 위해 추가하지 않았다. 인증/링크 기반 진입 작업에서 URL 계약을 정한다. |

FullCalendar 7의 기본 날짜 라벨 컨테이너는 `aria-hidden`이다. 인터랙티브 버튼으로 교체한 영역만 공개 `dayCellDidMount` hook에서 접근성 트리에 노출했다. 월이 바뀌는 동안 이전 DOM에 포커스를 주는 문제는 월별 렌더와 버튼 ref로 해결했다. 해당 구현은 설치 버전 변경 때 재검증한다.

## 실제 검증

- `pnpm test`: API 기존 단위 검사 **6개**, 웹 도메인 검사 **17개** 통과. 루트 test에 웹 검사를 연결해 기존 CI에서도 실행하도록 했다. 현재 변경은 아직 푸시하지 않아 GitHub CI 결과는 없다.
- `pnpm lint`: API/web 통과. 초기 공통 UI 파일의 Fast Refresh 경고는 표시 함수를 model로 옮겨 해결했다.
- `pnpm typecheck`: API/web와 새 테스트 소스 통과.
- `pnpm --filter web build`: TypeScript 및 Vite 프로덕션 빌드 통과.
- 브라우저: Codex 내장 브라우저에서 개발 서버 `127.0.0.1:5173`을 조작했다. 모든 네트워크/서버 동작은 미연결 상태다.
- 라이트 **320/360/768/1024/1440px × 캘린더/계좌·카드/월 합계 = 15개** 배치에서 문서 가로 넘침이 없었다. 360px 라이트와 320px 다크, 긴 모달을 시각 확인했다. 320px의 6주 달력도 넘침이 없었다.
- 등록: 10월 1일 식사 일정 생성→선택일 유지→수정/개인 전환, 9월 30일↔10월 1일 키보드 포커스, 월을 넘는 여행 표시를 확인했다.
- 금융: 60,000원 카드 지출의 10,000원 부분 환불 후 미납금 50,000원. 50,000원 납부 후 미납금 0원·본인 순지출 80,000원으로 납부가 재집계되지 않음을 확인했다.
- 360px에서 12,345원 지출 저장을 한 번 실패시켜 제목/금액이 유지되고 재시도 한 번만 반영됨을 확인했다. 취소 후 내역이 제거됐다. 별칭 계좌를 50,000원 시작 잔액으로 추가했다.
- 하늘 관점에서 개인 선물·급여·이체/납부가 제외되고 공유 지출 상세에 계좌 정보·수정 동작이 없는 것을 확인했다. 가상 데이터는 브라우저에 있으므로 서버 격리 시험을 뜻하지 않는다.
- 조회 오류 재시도·로딩 완료, 빈 달력/계좌/합계, Esc의 작성 중 확인, 확인 버튼으로 포커스 이동, 닫은 뒤 등록 버튼으로 복귀를 확인했다. 최종 브라우저 console error/warn은 없었다.
- 색 대비 계산에서 라이트의 보조 문구·종류 색을 보완했다. 주요 텍스트 조합을 재계산했으며 전체 WCAG 인증이나 스크린리더 검증을 주장하지 않는다.

실제 기기 소프트 키보드·VoiceOver/TalkBack, 운영 시차/동시성·API 권한·금융기관 연동은 미검증이다. 웹 도메인 테스트는 Node에서 실행하며 브라우저 확인은 이번 세션의 수동 자동화 기록이다. 재실행 가능한 브라우저 E2E 스위트는 아직 없다. API 코드는 변경하지 않아 DB 통합 검사·컨테이너 재빌드는 이번에 재실행하지 않았다.

실행 명령·실패와 수정은 [명령 기록](09_SETUP_COMMANDS.log)을 따른다. 웹만 체험할 때는 루트에서 `pnpm dev:web`를 실행하면 된다. Docker/API 없이 확인할 수 있다.

후속 주말·공휴일 개선과 추가 회귀 검사는 [공휴일 표시 기록](17_KOREAN_HOLIDAYS.md)을 따른다. 위 17개는 F-002 최초 검증이며 현재 웹 테스트는 공휴일 7개를 포함해 24개다.
