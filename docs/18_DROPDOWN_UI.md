# 공통 드롭다운 UI

확인일: 2026-09-27. 사용자 피드백에 따라 브라우저 기본 선택 목록을 앱의 따뜻하고 둥근 디자인에 맞게 교체했다.

## 설치 버전과 선택 근거

- React 19.3.0, Vite 8.3.1, TypeScript 6.0.3, Node 24.20.0, pnpm 11.24.0을 확인했다.
- [Radix Select 공식 문서](https://www.radix-ui.com/primitives/docs/components/select), npm 메타데이터, 설치된 타입과 배포 코드를 대조했다. `@radix-ui/react-select@2.3.7`은 MIT이며 React/React DOM 16.8~19 피어 범위를 제공한다. 이 프로젝트의 React 19에서 빌드와 브라우저 동작을 확인했다.
- `pnpm --filter web add --save-exact @radix-ui/react-select@2.3.7`로 설치했다. package.json과 lockfile은 CLI로 갱신했으며 전이 의존성을 포함해 38개 패키지가 추가됐다.
- 공식 API의 제어 상태, 키보드 선택, 포커스 관리, `Portal.container`, popper 위치 계산을 사용한다. 빈 문자열을 `Select.Item` 값으로 사용하지 않는 것은 라이브러리 제약이다. 색상·모서리·여백·애니메이션과 공통 래퍼 구성은 프로젝트 선택이며 공식 필수 디자인이 아니다.

## 적용 범위

- `SelectField` 공통 컴포넌트를 만들고 달력 공개 범위, 예시 사용자, 테마, 예시 상태, 거래 종류, 거래 계좌, 계좌 종류, 체크카드 연결 계좌 등 8개 선택 필드 위치에 적용했다.
- 선택 항목 체크, 포커스 표시, 긴 이름 줄바꿈, 라이트/다크 테마를 제공한다. 선택할 항목이 없으면 비활성화하고 안내 문구를 표시한다. 기존 폼 오류의 접근성 속성을 유지한다.
- 네이티브 `<dialog>` 안에서는 메뉴 포털을 해당 dialog에 둬 목록이 뒤에 가려지거나 비활성화되는 문제를 피했다. Escape 한 번은 목록만 닫고 입력창은 유지한다. 모달 초기 포커스도 새 선택 필드에 맞췄다.
- 앞서 제거한 주말·공휴일 범례는 다시 추가하지 않았다. 실제 인증·공유·금융 API와 데이터 영속화는 이번 범위에 없다.

## 실제 검증

- 웹 `lint`, `typecheck`, `build` 통과. 최초 타입 검사와 빌드는 선택적인 연결 계좌 ID를 필수 문자열에 전달해 실패했다. `linkedId ?? ""`로 미선택 값을 명시한 후 다시 통과했다.
- 기존 웹 테스트 26/26 통과. 이는 도메인·공휴일 회귀 검사이며 드롭다운 동작은 아래 개발 브라우저 확인으로 검증했다.
- 키보드 방향키/Enter로 공개 범위를 바꾸고 공유 기록만 남는 동작과 트리거 포커스 복귀를 확인했다. 설정 모달에서 Escape가 목록만 닫는 동작도 확인했다.
- 가계부 종류·계좌를 선택해 예시 이체를 저장하고 두 계좌 잔액 반영을 확인했다. 받는 계좌 누락 시 오류 속성, 체크카드의 은행 연결 저장, 계좌가 없는 상태의 비활성 선택 메뉴도 확인했다. 모두 임시 탭의 가상 데이터이며 실제 거래가 아니다.
- 320/360/768/1280px에서 메뉴가 화면 안에 표시되고 페이지 가로 넘침이 없음을 확인했다. 라이트/다크 화면, 바깥 클릭으로 닫기, 모달 내부 메뉴를 시각 확인했다. 최종 브라우저 console warn/error는 없었다.
- 실제 휴대폰과 스크린리더 검증은 수행하지 않았다. 임시 탭을 닫고 사용자 탭과 개발 서버는 유지했다. API/DB 검사는 이번에 다시 실행하지 않았다.

빌드 결과는 JS 578.54 kB / gzip 178.24 kB, CSS 43.96 kB / gzip 9.81 kB다. 직전 화면 대비 JS gzip이 29.62 kB 증가했으며 Vite의 단일 청크 500 kB 초과 경고가 발생했다. 빌드는 성공했지만 경고를 제거한 상태는 아니다. 운영 전 로딩 비용을 측정하고 필요하면 화면별 코드 분리를 검토한다.

실행 명령과 실패/수정은 [명령 로그](09_SETUP_COMMANDS.log), 전체 화면의 구현 경계는 [React UI 기록](16_REACT_UI_IMPLEMENTATION.md)을 따른다. 커밋·푸시·배포는 수행하지 않았다.
