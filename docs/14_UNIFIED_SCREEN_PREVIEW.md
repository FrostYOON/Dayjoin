# F-001 · 통합 캘린더와 가계부 화면 시안

작성일: 2026-09-26. 상태: **가상 데이터 시안 작성과 브라우저 동작 확인 완료**. 사용자 사용성·실제 앱·인증·금융 원장은 미검증 또는 미구현이다.

## 이번 결과

사용자가 요청한 계좌·카드·이체 포함 범위를 [통합 설계안](13_CALENDAR_RECORDS_PROPOSAL.md)에 따라 대화형 모바일 시안으로 구체화했다. 이전 D-002 일정 시안은 보존하고 이 채팅의 `Dayjoin Unified`를 새 시안으로 추가했다.

아이보리/따뜻한 차콜 바탕, 살구색 주요 버튼과 둥근 기록 행을 유지한다. 기록 종류는 일정 라벤더, 지출 테라코타, 수입/환불 블루, 이체/납부 중립색으로 표시한다. 공개 범위는 색과 별개로 자물쇠·사람 아이콘과 문구를 사용한다. 눌림/배경 전환은 짧게 적용하고 움직임 줄이기 설정을 따른다.

화면 순서: **항상 펼쳐진 월간 달력 → 기록 종류/공개 범위 필터 → 선택한 날짜의 기록과 등록**. 2026-09-26 사용자의 “처음부터 달력이 메인” 피드백을 반영했다. 보조 화면은 계좌·카드와 월 합계다. 사진이나 장식용 그래프를 추가하지 않고 날짜·금액·공개 대상에 집중한다.

## 화면과 동작

| 화면 | 표시 내용 | 시안에서 조작할 수 있는 것 |
|---|---|---|
| 캘린더 | 월간 달력과 종류별 표시·기록 수, 선택일의 일정·가계부 내역 | 이전/다음 달, 날짜 선택, 종류/공개 범위 필터, 선택일로 등록, 상세 열기 |
| 통합 등록 | 일정/가계부 구분, 종류별 필드, 저장 직전 공개 안내 | 일정 추가, 종일/시간 변경, 수입·지출·이체·카드 납부 입력, 공개 범위 선택 |
| 거래 상세 | 제목·금액·날짜·분류·작성자·공개 메모 | 본인 기록 수정/취소, 지출에서 부분 환불 등록. 타인의 공유 기록은 읽기 전용 |
| 계좌·카드 | 본인 현금/은행 잔액, 신용카드 미납/선납, 체크카드 연결 | 은행/현금/신용카드/체크카드 추가, 관련 기록 열기, 이체·납부 입력 진입 |
| 월 합계 | 내 장부 또는 공유 캘린더의 수입·순지출, 분류별 합계 | 조회 월·집계 기준 전환. 이체/납부 제외 및 환불 반영 확인 |

화면 아래 접힌 `시안 비교 설정` 안의 `보는 사람`, `화면 상태`는 시안 검토용이며 제품 메뉴나 실제 계정 전환 기능이 아니다. `나`는 지우, `다른 멤버`는 하늘이라는 가상 인물이다. 각 사람의 개인 거래와 계정, 서로 공유한 거래를 비교할 수 있다.

기록과 계정은 실행 중 메모리에서만 바뀌며 새로고침하면 예시 값으로 초기화된다. 조회 월·필터·관점 등 시안 설정만 복원할 수 있다. 입력한 제목·메모·금액은 호스트 설정 상태에 저장하지 않는다.

## 입력·오류·공개 안내

- 새 등록에서 일정과 가계부를 선택한다. 가계부로 전환하면 나만 보기를 기본으로 한다.
- 일정은 시작/종료와 종일 여부를, 가계부는 종류에 맞는 결제·입금 계정 또는 보내는/받는 계정을 표시한다.
- 가계부 금액은 양수 원화 정수다. 시안 상한은 9,999,999,999,999원이며 실제 서비스 한도는 별도 결정한다. 시작 잔액/미납금은 0원도 허용한다.
- 같은 계정 사이 이체, 계정 미선택, 종료 역전, 제목 누락, 환불 잔여 금액 초과 등을 텍스트로 안내한다.
- 저장 오류 상태에서는 입력을 보존하고 다시 저장할 수 있다. 계좌 추가도 동일한 실패/재시도 흐름을 제공한다.
- 계정이 없는 상황, 조회 오류와 복구는 상단의 상태 선택기로 검토한다. 빈 화면 선택은 데이터 삭제가 아니다.
- 공유받은 금융 거래에는 제목·금액·날짜·분류·공개 메모·작성자만 표시하고 원장의 계정 이름과 잔액, 수정/취소 버튼은 제공하지 않는다.

## 계산 시뮬레이션

금액은 `BigInt` 원화 정수로 계산한다. 예시 계정의 시작 금액과 취소되지 않은 거래를 바탕으로 잔액을 다시 산출한다. 은행·현금 합계는 카드 선납금을 포함한 총자산으로 표시하지 않는다. 계정 화면은 입력된 전체 거래 기준이며 월 보고서는 선택한 월 기준이다.

체크카드는 연결된 은행에만 반영한다. 신용카드 사용은 지출과 미납금을 늘리고 납부는 은행과 미납금을 줄인다. 이체·납부는 수입/지출에서 제외한다. 환불은 원 결제 수단에 반환하고 순지출을 줄이며 미납금이 음수면 선납으로 표시한다. 시작 금액을 수입/지출로 집계하지 않는다.

이는 화면 확인용 계산이다. 생산용 복식 원장, DB 트랜잭션, 변경 이력, 멱등키, 동시성, RLS가 구현되었다는 뜻이 아니다. 시안의 취소/수정 방식도 생산용 원장 저장 방식으로 재사용하지 않는다.

## 실제 브라우저 확인 · 2026-09-26

| 항목 | 확인 결과 |
|---|---|
| 개인/공유 관점 | 하늘 화면에 지우의 개인 선물·급여·생활 통장 없음. 공유 식사비는 보이되 계정 이름·잔액·수정 버튼 없음 |
| 공개 범위 변경 | 식사비를 개인으로 바꿔도 내 장부 순지출 유지, 다른 멤버의 식사비 목록에서는 제외 |
| 이체 입력/오류 | 같은 계정 선택 거부. 10,000원 이체 후 생활 통장 3,440,000원 / 여행 통장 330,000원 |
| 저장 실패/재시도 | 이체와 수입 수정에서 제목 보존 및 재시도 반영 확인 |
| 카드 납부 | 위 이체 후 60,000원 납부 시 생활 통장 3,380,000원 / 미납금 0원. 개인 순지출은 90,000원 유지 |
| 부분 환불 | 60,001원 환불 거부. 10,000원 환불 후 카드 선납 10,000원 / 개인 순지출 80,000원 / 공유 순지출 62,000원 |
| 계정 추가 | 시작 잔액 50,000원 계정 추가 후 수입 합계 유지. 새 체크카드에서 연결 계좌의 50,000원 표시 |
| 체크카드 사용 | 초기 데이터에서 15,000원 사용 후 생활 통장 3,435,000원, 신용카드 미납금 60,000원 유지 |
| 기록 취소 | 초기 데이터의 개인 선물 30,000원 취소 후 생활 통장 3,480,000원 / 개인 순지출 60,000원 |
| 수입·편집 | 취소 확인 후 100,000원 수입 등록 시 수입 합계 2,600,000원. 제목 수정·오류 재시도 반영 |
| 여행 일정 | 종일·9월 30일~10월 2일 유지, 10월 조회에도 표시 |
| 기본 공개/금액 | 신규 가계부 기본값 나만 보기, 0원 거래 거부 확인 |
| 반응형 | 다크 모드 320·360·736px에서 54개 조합, 라이트 320·360px에서 12개 조합: 총 66개에서 가로 넘침·컨트롤 이탈 없음 |
| 브라우저 오류 | 최종 확인한 console error 목록 없음 |

위 수치들은 각 독립 검증 시점의 가상 데이터다. 새로고침 사이의 시험을 하나의 연속 원장으로 합산하지 않는다. 라이트 검증은 원본의 색상 설정만 강제한 임시 복사본을 사용했고 최종 원본은 시스템 모드를 따른다.

빠른 관점/필터 변경 뒤 호스트 상태 복원이 상세 화면을 목록으로 돌리는 문제를 발견했다. 키 순서와 무관하게 상태를 비교하고 이미 전송한 설정의 되돌아온 알림을 무시하도록 수정했다. 이후 빠른 관점·필터→상세 전환 4회, 수입 등록/편집/재시도와 취소 흐름을 재확인했다. 다른 멤버 관점의 작성자 표시는 상대적인 `나` 대신 가상 이름으로 수정했다.

## 검증 한계와 다음 구현

### 달력을 첫 화면으로 변경한 추가 확인 · 2026-09-26

- 월간 달력은 처음부터 표시하며 접기 기능을 제거했다. 기본 예시는 2026년 9월 26일이다. 월 이동 시 새 달의 1일을 선택한다. 같은 날짜를 다시 눌러도 선택을 유지한다.
- 날짜 칸의 표시와 건수는 선택한 관점·필터로 볼 수 있는 기록에서만 계산한다. 다른 멤버 관점에서 개인 급여의 9월 25일은 `기록 없음`이며, 공유 필터의 9월 26일은 일정 1건·지출 2건이다. 이 확인은 서버 권한 시험이 아니다.
- 날짜 선택으로 아래 목록 변경, 10월 1일에 9월 30일~10월 2일 여행 표시, 선택일로 일정/가계부 등록 진입을 확인했다. 10월 1일 일정을 저장한 뒤 해당 날짜 선택과 `일정 2건` 표시가 유지됐다.
- 빈 날짜의 등록 버튼, 종류 필터, 조회 오류에서 달력 유지·기록 표시는 숨김·재시도 후 복구를 확인했다.
- 다크 320/360/736px × 정상/빈 상태/오류/6주 월간 달력 = 12개, 라이트 동일 너비의 정상 달력 3개: 총 15개 추가 배치에서 가로 넘침/컨트롤 이탈 없음, 달력이 필터보다 위에 있음. 위의 66개는 이전 시안 검증 기록이며 이번에 전부 재실행한 것은 아니다.
- 네이티브 월 입력에 대한 자동 `fill`은 도구에서 실패했다. 해당 방식으로 직접 월 지정은 검증하지 않았고, 이전/다음 달 버튼으로 월 전환과 6주 달력을 확인했다. 최종 브라우저 console error는 없었다.
- 공식 기준: [WCAG 2.2 Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)를 2026-09-26 다시 확인했다. 색 외에도 모양·범례·종류 문구·날짜 접근성 이름을 사용한다. 달력의 크기/배치/기본 선택일은 사용자 피드백을 반영한 프로젝트 설계 선택이며 WCAG가 지정한 화면 구조는 아니다.

### 구현 범위

- 모든 금융 정보는 예시이고 브라우저 안에 존재한다. 화면에서의 비표시는 보안 검증이 아니다. 실제 서버 조회 권한·계좌 정보 차단은 F-010/F-040에서 시험한다.
- 실제 로그인·은행/카드 연동·송금·영속 저장·초대·알림·내보내기는 연결하지 않았다. 계좌 별칭 변경/비활성화와 화면 이탈 시 입력 손실 확인도 다음 구현 범위다.
- 실기기·전체 키보드/스크린리더·대규모 데이터·운영 시간대·실제 사용자 사용성은 검증하지 않았다. 호스트 디자인 설정 패널 자체는 로컬 렌더러에서 조작 시험하지 않았다.
- F-001 시안 산출물만 완료했다. 다음 프론트엔드 단계는 이 구성을 React + Vite + TypeScript의 가상 데이터 화면으로 옮기는 F-002다. 실제 원장·공유는 D-020과 F-010 이후 연결한다.

## 근거와 도구

설치 메타데이터 확인: React 19.3.0, Vite 8.3.1, TypeScript 6.0.3. 이번 시안은 HTML/DOM이며 새 라이브러리를 설치하거나 앱 소스를 수정하지 않았다. 공식 계산·권한·색상 참고와 사용자 결정의 구분은 [설계안의 근거](13_CALENDAR_RECORDS_PROPOSAL.md#근거와-확인--2026-09-26)를 따른다. 실제 터미널·검증 기록은 [명령 로그](09_SETUP_COMMANDS.log)에 남긴다.

## 후속 상태 · 2026-09-26

이 문서는 F-001 시안 검증의 역사 기록이다. 이후 [F-002 React 통합 화면](16_REACT_UI_IMPLEMENTATION.md)을 `apps/web`에 구현했다. 시안의 66개 검사 수치를 React 앱 검사 결과로 재사용하지 않으며, 현재 앱의 실행·검증·제한은 후속 문서를 따른다.
