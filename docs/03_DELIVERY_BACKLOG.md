# Dayjoin 개발 순서와 백로그

계획 v0.3: NestJS 경험을 활용한다. 아래 공수에는 프론트 학습과 Nest API/Prisma/RLS 검증·배포를 포함하는 것으로 재정의했으며 실제 소요시간은 미검증이다. 기반 단계에서 부족하면 기능 범위 또는 일정을 재산정한다. Nest 입문 강의를 처음부터 반복하지 않고 필요한 부분을 구현하며 보완한다.

## 시간 가정

프론트엔드 입문을 포함한 **초대 베타 160~220시간**, 주 10시간을 모두 이 서비스에 쓸 때 16~22주를 계획 범위로 둔다. 불확실성 30%를 포함하면 약 21~29주다. 날짜 약속이 아니라 첫 2주 실측으로 다시 계산할 추정치다. 인터뷰 대기·공급자 심사·출시 후 운영 시간은 별도다.

개인 v0는 앞부분의 약 40~60시간에서 목표로 한다. 이때는 공유/권한/운영 품질이 완료된 상태가 아니다. 반복 일정·이메일 리마인더는 추가 30~50시간, 유료 결제/정책/운영 보강은 추가 30~60시간 후보이며 베타 결과에 따라 재산정한다.

| 단계 | 시간 | 산출물 | 다음 단계 조건 |
|---|---:|---|---|
| D0 학습/흐름 | 30~40h | HTML/CSS/React 폼·익숙한 TS 활용, 가상 일정 목록, 첫 사용자 흐름 | props/state/폼 오류를 직접 설명하고 수정 |
| D1 기반 | 20~30h | web/api workspace·Nest API·Prisma·Auth·CI | 깨끗한 환경에서 설치/빌드/로그인 재현 |
| D2 그룹/권한 | 25~35h | 그룹·멤버·초대·Nest 권한·RLS | 타 그룹/탈퇴/만료 초대 공격 테스트 통과 |
| D3 일정 | 30~40h | 개인/공유 일정·월/목록·동시 수정 | 시간대/종일/충돌 인수 조건 통과 |
| D4 변경 확인 | 20~25h | 알림함·설정·내보내기/탈퇴 | 삭제/탈퇴 후 접근과 알림 정리 |
| D5 베타 준비 | 35~50h | E2E·모바일·메일 인증·배포·복원 시험 | 5개 그룹 초대 시험을 시작할 수 있음 |

## 첫 2주: 20시간

| ID | 시간 | 작업 | 완료 조건 |
|---|---:|---|---|
| D-001 | 2h | 사용자 본인의 일정 공유 사례 3개와 첫 그룹 유형 선택 | 누가/언제/무엇을 공유하는지 문서로 적음 |
| D-002 | 3h | 종이/간단한 와이어프레임: 목록·입력·초대 | 정상/빈 화면/오류 3상태 표시 |
| D-003 | 5h | HTML/CSS, Flex/Grid 학습과 익숙한 TS로 화면 작성 | 360px에서 입력 폼 사용 가능 |
| D-004 | 4h | React props/state/event, controlled form | 입력→검증→목록 반영 직접 구현 |
| D-005 | 3h | Node/pnpm/Git 환경 확인, Vite 기반 구성 | 설치 버전·실행법 기록, 빌드 성공 |
| D-006 | 3h | 가상 일정 목록과 단일 일정 추가 | 새로고침 손실/서버 미연결 상태를 명확히 표시 |

20시간에 전부 완료되지 않으면 다음 주로 넘기며 로그인/결제까지 억지로 추가하지 않는다. 학습 결과는 서비스 안의 작은 화면으로 남긴다.

- [ ] D-010: web/api workspace, Nest health/DTO/오류 계약, formatter/lint/typecheck/build/CI 구성. 의존: D-005. 산출물: 실제 실행 로그.
- [ ] D-020: Auth JWT Guard, Prisma/RLS transaction helper, workspaces/memberships migration. 의존: D-010. 산출물: 두 사용자 격리 시험.
- [ ] D-021: 초대 발급·회수·수락과 마지막 owner 정책. 의존: D-020. 산출물: 병렬 수락/만료/탈퇴 시험.
- [ ] D-030: events 시간 CHECK와 Nest 일정 Service 트랜잭션. 의존: D-020. 산출물: 종일·자정·기간 겹침·중복 생성 시험.
- [ ] D-031: 월/목록·입력 폼·revision 충돌 UI. 의존: D-030. 산출물: 서울/토론토 수동 점검.
- [ ] D-040: 변경 알림, 읽음 처리, 멤버십 취소 반영. 의존: D-021/D-031.
- [ ] D-041: 내보내기와 탈퇴/삭제 흐름. 의존: D-040. 산출물: 권한 및 CSV 수식 주입 방지 점검.
- [ ] D-050: 외부 SMTP, Nest container/health·web 배포, 백업과 복원 연습. 의존: 핵심 P0 통과. 산출물: 복원 보고서.
- [ ] D-051: 5개 그룹 온보딩과 4주 관찰. 의존: D-050. 산출물: 활성화/재사용/불편 기록.
- [ ] D-060: 반복 일정/리마인더 필요성 판정 후 P1 구현. 의존: D-051.
- [ ] D-070: 유료 가치/가격 후보 시험, PG 테스트, 해지/환불. 의존: 반복 사용 증거와 가맹 조건 확인.

매주 10시간 예시: 2시간 학습/설계, 5시간 구현, 2시간 검증, 1시간 기록/피드백. 구현 중 작업은 1개, 크기는 2~5시간으로 나눈다. 완료 기록에는 변경 내용·검사 결과·남은 위험을 적는다. 코드 생성 도구의 결과도 본인이 실행하고 설명할 수 있어야 한다.

첫 베타 출시 체크: P0 완료, 권한 격리, 시간대, 복원, SMTP 인증, 모바일, 개인정보/삭제 안내, 오류 모니터링. 성능 수치는 실제 측정 후 기록하며 계획 목표를 통과 결과로 적지 않는다.
