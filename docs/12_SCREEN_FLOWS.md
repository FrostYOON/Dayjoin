# D-002 · 모바일 화면 흐름과 와이어프레임

작성일: 2026-09-26. 상태: **설계 초안 작성 및 미리보기 동작 확인 완료 / 사용자 사용성 검증 전**.

후속 범위 안내: 이 문서와 미리보기는 일정 중심 D-002 결과다. 사용자는 이후 계좌·카드·이체까지 포함한 가계부 통합을 제시했다. 최신 [통합 설계안](13_CALENDAR_RECORDS_PROPOSAL.md)과 F-001 화면 작업을 먼저 반영하며, 아래 완료 결과를 금융 기능 검증으로 해석하지 않는다.

## 목적과 범위

가족·커플이 저녁식사와 여행을 공유하는 첫 흐름을 목록, 일정 입력, 멤버·초대, 초대 수락 화면으로 구체화한다. 가족 관계에 종속된 전용 기능 없이 그룹·멤버·일정 구조를 유지한다.

이 채팅의 `Dayjoin D002` 미리보기는 예시 데이터로 동작하는 설계 도구다. 화면/상태 선택기는 검토용이며 실제 제품 메뉴가 아니다. 앱의 React 예제 화면이나 Nest API는 이번 작업에서 변경하지 않았다. 아래 구조와 상태 표는 미리보기 없이도 다음 구현에 사용할 수 있는 기준이다.

- 생성자 화면의 전제: 로그인과 그룹 생성이 끝났고 본인이 owner다. `우리 둘`과 멤버 2명은 화면용 가상 데이터다.
- 초대받는 화면의 전제: 수락 전에는 그룹 이름·멤버·일정 데이터를 표시하지 않는다.
- 미리보기의 추가·수정은 메모리에만 반영하고 새로고침 시 초기화한다. 실제 로그인·저장·링크 발급·공유·가입은 일어나지 않는다.
- 이번 산출물은 D-002다. D-003~006의 React 화면, D-020의 인증/권한, D-021의 실제 초대, D-030~031의 일정 저장/조회 완료와 구분한다.

## 화면 구성 결정

시각 방향(사용자 피드백 반영): **부드럽고 따뜻한 색감 + 둥근 화면**. 초기 녹색 초안을 대체해 아이보리 바탕, 짙은 브라운 글자, 살구색 포인트를 사용한다. 다크 모드는 따뜻한 차콜 바탕으로 대응한다. 초록색은 브랜드 제약이 아니며 정확한 색상 값은 아직 프로젝트 제안이다.

날짜·제목을 먼저 읽도록 크기와 굵기를 구분하고, 낮은 대비의 경계와 여백으로 화면을 정돈한다. 일정 행은 둥근 클릭 영역으로 만들며 공유 범위 안내는 작은 아이콘과 문구로 줄인다. 목록·입력·초대·수락이 같은 입력창과 버튼 형태를 공유한다. 로즈·버터 포인트와 밝기·모서리 정도는 미리보기 디자인 설정에서 비교할 수 있다. 기본 밝기는 시스템을 따른다.

내용 순서: 현재 캘린더와 공유 범위 → 날짜·시간과 일정 제목 → 추가/수정 → 그룹의 멤버·초대. 제품 화면의 문구는 사용자가 수행할 동작을 설명한다.

상호작용: 일정 행을 눌러 편집 화면으로 이동한다. 모바일 편집은 날짜 입력과 키보드 공간을 확보하는 전체 화면으로 시작한다. 종일 여부에 따라 시간 입력을 바꾸며 날짜와 기존 입력을 보존한다. 동작 상태는 문구로도 표시한다. 버튼의 색상/눌림 반응만 짧게 적용하고 움직임 줄이기 설정에서는 전환을 제거한다.

| 화면 | 우선 보여줄 내용 | 주요 동작 | 종료/이동 |
|---|---|---|---|
| 일정 목록 | 현재 캘린더, 개인/공유 표시, 날짜순 일정, 시간 기준 | 일정 추가, 일정 선택, 캘린더 전환 | 입력 또는 멤버·초대 |
| 일정 입력/수정 | 저장할 캘린더, 공개 범위, 제목, 시작/종료, 종일, 메모 | 저장, 입력 오류 수정, 재시도 | 성공 후 선택한 캘린더의 목록 |
| 멤버·초대 | 현재 멤버와 역할, 초대 권한, 링크 상태 | owner의 링크 발급·회수 | 목록 또는 초대받는 화면 |
| 초대 수락 | 로그인 필요 여부, 부여될 권한, 초대 상태 | 로그인 후 복귀, 수락 | 참여 성공 후 그룹 목록 |

전체 제품의 알림·설정 탭, 데스크톱 월 보기, 기간 필터, 그룹 생성 화면, 삭제 확인과 탈퇴는 기존 PRD 범위를 유지하며 이번 와이어프레임에서 동작을 구현하지 않는다.

## 텍스트 와이어프레임

### 일정 목록

```text
Dayjoin
다가오는 일정
저녁 약속부터 다음 여행까지.
보고 있는 캘린더
[우리 둘 · 공유 ▾]                    [멤버·초대]
나와 상대방, 2명이 함께 보고 있어요
예정된 일정 2                         서울 시간 · 날짜순

9월 26일  함께 저녁식사                    ›
          19:00 – 20:30 / 우리 둘
9월 30일  가을 여행                        ›
          9.30 – 10.2 / 종일 / 우리 둘

[ + 일정 추가 ]
```

일정 행 전체를 누를 수 있고 색 외에 캘린더 이름과 공유 여부를 표시한다. 개인 캘린더로 바꾸면 개인 일정만 표시한다. 보기 전용 멤버에게는 공유 일정 추가 동작을 제공하지 않는다.

### 일정 입력/수정

```text
‹ 일정 목록
새 일정 / 일정 수정
저장할 캘린더 [우리 둘 · 공유 ▾]
이 일정은 우리 둘에게 보여요.
일정 제목 [함께 저녁식사]
[ ] 종일 일정
시작 날짜 [2026-09-26]   종료 날짜 [2026-09-26]
시작 시간 [19:00]        종료 시간 [20:30]
시간 기준: 서울 (Asia/Seoul)
메모 · 선택 [장소나 함께 알아둘 내용]
[오류가 있다면 원인과 수정 방법]
[ 저장 ]
```

좁은 화면에서는 날짜/시간 필드를 세로로 배치한다. 대상 캘린더는 현재 보고 있는 캘린더를 기본값으로 하고 공유 범위를 항상 확인할 수 있게 한다. 미리보기는 그룹 1개와 개인 캘린더 1개를 제공한다. 실제 구현에서는 쓰기 권한이 있는 캘린더만 선택할 수 있어야 한다.

### 멤버·초대와 수락

```text
‹ 일정 목록                    초대받은 사람
멤버·초대                      함께 일정을 공유해요
우리 둘                        참여 권한: 편집 가능
나 / 관리자                    수락한 뒤 그룹 일정을 볼 수 있어요.
상대방 / 편집 가능
초대 권한 [편집 가능 ▾]         [로그인 후 계속] → [초대 수락]
발급 후 7일
[링크 복사] [링크 회수]         성공 → 그룹 목록
```

제품에서는 복사 성공/실패를 안내한다. 미리보기에는 실제 복사 대신 `초대받는 화면 보기`를 둬 링크가 발급되거나 전송되는 것으로 오인하지 않게 했다. 초대 회수는 기존 멤버 탈퇴나 권한 회수가 아니다. 권한을 바꾸면 새 링크를 발급해야 하며 기존 링크의 권한이 자동 변경된다고 표시하지 않는다.

## 두 사용 사례의 흐름

### 저녁식사 · 시간 지정

1. 현재 캘린더가 `우리 둘 · 공유`인지 확인하고 일정 추가를 누른다.
2. 제목, 날짜, 시작/종료 시각을 입력한다. 장소는 메모에 적는다.
3. 저장에 성공하면 해당 캘린더 목록으로 돌아와 날짜·시간과 제목을 확인한다.
4. 일정 행을 눌러 약속 시간을 수정한다. 실제 공유 단계에서는 변경자/변경 시각과 알림을 연결한다.

예시: 2026-09-26 19:00–20:30, Asia/Seoul. 실제 사용자의 약속이 아니다.

### 여행 · 여러 날짜

1. 일정 추가에서 종일을 켜고 시작일과 마지막 여행일을 지정한다.
2. 화면은 선택한 종료 날짜까지 포함하는 것으로 설명한다. 예시는 2026-09-30부터 2026-10-02까지다.
3. 목록에 전체 날짜 범위와 종일 표시를 유지해 월이 바뀌어도 기간을 이해할 수 있게 한다.
4. 종일을 끄면 출발·도착 시각도 입력할 수 있다. 여행을 항상 종일로 강제하지 않는다.

날짜만 있는 종일 일정은 시간대 변환으로 날짜가 바뀌지 않아야 한다. API/DB의 종료일 포함·배타 표현은 D-030에서 명시적으로 매핑하고 시간대 테스트로 확인한다. 화면상의 포함 규칙을 저장 형식 결정으로 오해하지 않는다.

## 상태별 동작과 복구

| 화면 | 정상 | 빈 상태/최초 입력 | 오류와 복구 | 추가 상태 |
|---|---|---|---|---|
| 목록 | 날짜순 일정과 공유 범위 | `아직 일정이 없어요` + 일정 추가 | `일정을 불러오지 못했어요` + 다시 시도 | 로딩 중에는 빈 목록으로 오인시키지 않음. 접근 상실 시 이전 그룹 정보를 숨기고 내 캘린더로 이동 |
| 입력/수정 | 기존 값 또는 새 입력 | 제목이 비어 있으면 제목 입력 안내 | 저장 실패 시 값을 유지하고 재시도. 필수값/날짜 역전은 저장 전 안내 | 동시 수정은 자동 덮어쓰기 없이 최신 내용 비교. 보기 전용에는 저장 동작 없음 |
| 초대 발급 | 권한·유효기간·활성 링크 | 링크 없음 + 만들기 | 발급 오류 시 선택한 권한을 유지하고 다시 만들기 | 만료/회수는 새 링크 발급 안내. 관리 권한 없으면 링크·관리 동작을 제공하지 않음 |
| 초대 수락 | 권한 안내와 수락 | 로그인 전에는 로그인 후 초대로 복귀 | 수락 실패는 성공으로 안내하지 않고 재시도 | 만료/회수된 링크는 수락 불가. 그룹 데이터 없이 새 링크 요청 안내 |

권한 제한은 이 단계에서 화면 표현과 예시 흐름만 확인했다. 버튼 숨김은 보안 경계가 아니며, 실제 접근 제어는 Nest와 PostgreSQL/RLS에서 별도로 구현·시험한다.

## 다음 구현의 인수 조건

- 제목 공백만 입력하거나 필수 날짜가 없으면 저장하지 않고 오류를 설명한다.
- 시간 지정 일정은 종료 시점이 시작보다 뒤여야 한다. 자정을 넘기는 일정은 날짜까지 비교한다.
- 종일 일정은 같은 날짜도 허용한다. 시작일보다 앞선 종료일은 허용하지 않는다.
- 저장 실패 시 제목·대상 캘린더·날짜/시간·종일·메모를 보존한다. 성공과 실패의 안내를 구분한다.
- 개인 캘린더에 추가한 일정이 공유 목록으로 섞이지 않는다. 권한이 없는 캘린더는 쓰기 대상으로 선택할 수 없다.
- 변경 중인 화면을 나갈 때 입력 손실을 확인한다. 실제 앱의 키보드/뒤로 가기 동작과 함께 구현한다. 이 확인 UI는 이번 미리보기에는 포함하지 않았다.
- 기존 PRD의 수정 충돌, 삭제 대상 확인, 변경자/변경 시각은 실제 일정 편집 단계에서 연결한다.
- 초대 수락 성공이 확인된 후에만 그룹 목록으로 이동한다. 로그인 왕복 후에도 같은 초대로 돌아온다.
- 각 입력에는 명시적 레이블이 있고 오류는 텍스트와 접근성 알림으로 전달한다. 주요 동작은 터치뿐 아니라 키보드로도 사용할 수 있게 구현한다.

설치 상태 확인: Node 24.20.0, React 19.3.0, Vite 8.3.1, TypeScript 6.0.3. 이번 미리보기는 문서용 HTML/DOM 상태 시뮬레이션이며 의존성 설치·버전 변경·앱 빌드는 수행하지 않았다. 후속 앱 화면은 기존 React + Vite + TypeScript 기준으로 구현한다.
